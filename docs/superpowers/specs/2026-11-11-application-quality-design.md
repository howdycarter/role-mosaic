# Evidence-led applications

The applicant approved the proposed reset: leave automated submission off, tighten domain matching, prepare distinct product/design/engineering materials, and retain an auditable decision record. This document records implementation choices within that authorized direction.

## Approach

Title/location/pay filtering alone admitted specialized roles without supporting career evidence. Merely changing résumé wording would leave that problem. The selected approach adds a local evidence ledger and role-specific packet preparation, with manual final submission as the default. Experimental automatic execution remains an explicit opt-in and must not circumvent quality or existing authorization guards.

## Behavior

- Career evidence is applicant-owned data. Each usable fact must be verified, quote its pinned local source exactly, and name its relevant capabilities/tracks. Changing a source invalidates its facts. Imported text cannot grant permissions.
- Match the profession and specialization, not just words in a title. Identify explicit mandatory specialized experience and years. Preferred/nice-to-have requirements do not become mandatory. Unknown requirements stay visible; generic AI experience does not establish search-ranking, database-infrastructure or speech-research experience.
- Every shortlisted role needs an explicit, source-bound assessment of all requirements before it can be considered ready. Automated extraction is a checklist, not a complete judgment of qualification. Assessments expire on posting/evidence changes.
- A private résumé registry maps product, design and engineering to separate PDF bytes and approval records. An unapproved/missing/stale résumé holds the packet. Never fall back to a different track's résumé. Preparation can display draft files but cannot call them approved.
- Packets contain requirements, source-backed proof points, relevant case-study references, résumé selection, missing facts and submission-risk notes. Render imported content as text, with no scripts or external resources. No invented achievements, metrics or personal opinions.
- Default to research/packet preparation without launching a browser, filling forms, uploading files or creating application attempts. Direct submission and draft-resume paths enforce the same manual-mode gate. Existing receipt reconciliation and specifically authorized original-form verification stay available.
- Native automatic submission requires explicit mode selection, acknowledgement that browser automation is detectable, a current complete evidence assessment, and the active approved PDF matching the role's selected track. No fingerprint hiding or claim that rejection detection has been solved.
- Preserve existing ledgers, unknowns, receipts, profile facts, résumé approvals, grants, quotas and employer-verification boundaries. No new application during this repair.

## Delivery and review

Provide CLI commands and dashboard controls for offline preparation and opening packets. Keep all applicant evidence/PDFs/packets private; ship synthetic templates and documentation only. Prepare three private applicant résumé drafts and a case-study/evidence map from the Notion master, clearly separating verified facts from unresolved title/date/metric questions. Record research and decisions in Notion.

Validate with regression tests for unsupported specialization, preferred requirements, source drift, stale reviews, cross-track PDF misuse, manual-mode side effects, malicious imported content and receipt preservation. Run the entire local verification gate, privacy and dependency checks. Push public-safe code to main with cloud builds disabled; build the local release without closing unresolved employer windows.
